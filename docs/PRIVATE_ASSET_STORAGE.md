# SIE-006 private object storage and quarantine

Private S3-compatible storage uses **separate quarantine and clean buckets**; presigned upload URL binds object key, type, content size, SHA256 checksum, server-side encryption and short expiry. Uploaded objects are never readable through user API until malware scanning, actual SHA256 and byte-count verification, and MIME inspection pass. Streaming ClamAV INSTREAM scanner uses a configured local Unix socket and rejects scanner errors/timeouts, malware, bad bytes, bad MIME and oversized streams. Accepted objects are promoted into private clean bucket, source quarantine cleaned up. Download links expire, check membership, and are only minted for `clean` assets.

No publicly accessible URL/policy, S3 credentials, bucket or ClamAV service is provisioned in this PR; production configuration and E2E S3+ClamAV integration test on an authorized target remain gates. Worker `workerPool` must be a separately protected privileged principal, never user-supplied. Large files are scanned streaming up to 1 GiB; multipart >1 GiB is separate capability. Text/plain sniff currently rejects unrecognized binary media. Malware scanned input is still untrusted and must never be executed by the service.
